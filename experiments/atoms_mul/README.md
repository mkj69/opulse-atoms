# Experiment 1: is multiplication innate or invented?

The first atoms-v2 experiment (design doc, section "first experiment"). It asks
whether a learner can invent a general repeated-addition definition (a
multiplication) and whether saving it in a definition library helps on unseen
dot-product tasks. See [PREREG.md](PREREG.md) for hypotheses,
outcomes, and decision rules; [INTERFACE.md](INTERFACE.md) is the module contract.

## Groups

- **A:** arithmetic operations include `mul`; definitions can persist.
- **B:** no `mul`; definitions can persist.
- **C:** no `mul`; definitions are local to one task.

Stage 1 contains 24 repeated-addition tasks; stage 2 contains 16 unseen
dot-product tasks. Each task has public examples and hidden exact tests.
AML definitions use typed ASCII syntax, for example
`op rep(n: Nat, x: Nat) -> Nat = if is_zero(n) then 0 else add(x, rep(pred(n), x))`.
Library listings mark saved definitions with their layer (`L1`, `L2`, etc.).
These worlds open invention of operations only; other atom kinds cannot be stored.

## Layout

`atoms_mul/kernel/` implements AML parsing, checking, execution, libraries and
equivalence; `atoms_mul/tasks/` builds the frozen `tasks/` files;
`atoms_mul/harness/` renders learner prompts, runs episodes and aggregates
results. `atoms_mul/analysis/` computes preregistered statistics and costs;
`worlds/` holds frozen group declarations; `runs/` holds reproducible dry runs.
Scripted dry-run statistics are diagnostics, not evidence for the learner hypothesis.
The machine track shares the harness and analysis but uses MASM programs and byte-state
tasks generated by `atoms_mul.machine.tasks` (generator version 2).

From the repository root, set `PYTHONPATH=src:experiments/atoms_mul` for all
commands below. To verify or regenerate frozen task/world declarations, run:

```sh
python -m atoms_mul.tasks.generate --out experiments/atoms_mul/tasks
python -c 'from atoms_mul.kernel.worlds import write_worlds; write_worlds("experiments/atoms_mul/worlds")'
python -c 'from atoms_mul.kernel.core_library import write_decls; write_decls()'
```

Do not regenerate frozen files for an actual experiment without preregistering
the change. To reproduce the offline runs:

```sh
python -m atoms_mul.harness.run --policy inventor --groups A,B,C --episodes 2 --run-id dryrun_inventor --out experiments/atoms_mul/runs
python -m atoms_mul.harness.run --policy nosave --groups B,C --episodes 2 --run-id dryrun_nosave --out experiments/atoms_mul/runs
python -m atoms_mul.harness.run --policy unroll --groups A,B,C --episodes 1 --run-id dryrun_unroll --out experiments/atoms_mul/runs
python -m atoms_mul.harness.run --policy flaky --groups B --episodes 1 --run-id dryrun_flaky --out experiments/atoms_mul/runs
python -m atoms_mul.analysis.analyze --run experiments/atoms_mul/runs/dryrun_inventor
python -m atoms_mul.analysis.cost --prompts experiments/atoms_mul/runs/dryrun_inventor/prompts.jsonl --episodes 40
python -m atoms_mul.harness.run --track machine --policy inventor --groups A,B,C --episodes 2 --run-id dryrun_machine_inventor --out experiments/atoms_mul/runs
python -m atoms_mul.harness.run --track machine --policy nosave --groups B,C --episodes 2 --run-id dryrun_machine_nosave --out experiments/atoms_mul/runs
python -m atoms_mul.harness.run --track machine --policy unroll --groups A,B,C --episodes 1 --run-id dryrun_machine_unroll --out experiments/atoms_mul/runs
python -m atoms_mul.harness.run --track machine --policy flaky --groups B --episodes 1 --run-id dryrun_machine_flaky --out experiments/atoms_mul/runs
python -m atoms_mul.analysis.analyze --run experiments/atoms_mul/runs/dryrun_machine_inventor
python -m atoms_mul.analysis.cost --prompts experiments/atoms_mul/runs/dryrun_machine_inventor/prompts.jsonl --episodes 40
```

The real run uses `LLMPolicy`; **requires supervisor approval; do not run**:

```sh
python -m atoms_mul.harness.run --policy llm --allow-api --model MODEL_APPROVED_BY_SUPERVISOR --groups A,B,C --episodes 40 --run-id real --out experiments/atoms_mul/runs --max-attempts 3 --fuel 200000
python -m atoms_mul.harness.run --track machine --policy llm --allow-api --model MODEL_APPROVED_BY_SUPERVISOR --groups A,B,C --episodes 40 --run-id real_machine --out experiments/atoms_mul/runs --max-attempts 3 --fuel 200000
```

It requires `OPENAI_API_KEY` (and optionally `OPENAI_BASE_URL`) and explicitly
opted-in API access. Each finished episode is appended to
`runs/<id>/episodes.jsonl` after a configuration header; after an interruption, rerun
with `--resume` to skip finished (group, episode) pairs. Resume validates the run
configuration (groups/episodes may grow), and also skips finished episodes after a
successful run by reading its final artifacts. Final artifacts are atomically replaced
before removing the checkpoint. The LLM requires a nonempty API key before creating a run
directory; malformed responses receive up to three API retries.
The configuration pins task files and all three AML world declarations, or the machine
world declaration and its group-A extension. A torn final checkpoint line is discarded
and its episode rerun; malformed earlier lines are rejected without discarding data.
An existing nonempty run directory cannot be reused without `--resume`; reproduce a
dry run with a fresh output directory, or resume its matching configuration.
