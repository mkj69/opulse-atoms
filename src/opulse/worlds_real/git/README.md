# Real Git three-way merge

This world models regular UTF-8, LF-terminated text files in a commit DAG. The reference model independently computes the unique best merge base, trees, file paths, and first-parent patch replay. Its line-hunk atom calls the real `git merge-file` plumbing implementation, so overlapping edits and conflict markers follow Git's actual text-merge algorithm rather than a guessed approximation. The oracle instead initializes a separate repository, commits both branches and runs `git merge --no-ff`, `git cherry-pick`, or `git rebase`. It compares worktree contents, unmerged paths, merge base, diff paths, log subjects and porcelain status. Temporary repositories live in the system temporary directory and are removed automatically.

Scope: no custom merge drivers, attributes, rename detection, symlinks, submodules, binary files, criss-cross ancestry or multiple merge bases. Text edits are deliberately newline-terminated. For conflicted cherry-picks, the only normalization is the commit-hash-and-subject marker label to the abstract `topic` name; the rest of the worktree must match exactly. No assertion is made about unsupported cases.

Inputs reject non-UTF-8 text and paths, including lone surrogates. Cross-branch file/directory conflicts retain the directory and move the colliding file to Git's `~HEAD` or `~topic` path. `MergeReview.make` validates the complete result and wraps a checked `clean` or `conflicted` classification.

`world.py` exposes a round-trippable `opulse.world/2` declaration, four open kinds, ten typed inventions (curriculum lessons; declared dependency layers are checked by the core), and a five-level ladder. `build_library()` binds layer-zero host operations to the reference model; `promote_curriculum()` checks, unfolds, verifies, accounts for and promotes every definition over its recorded bounded example. Bounded evidence does not claim correctness outside those examples. `showcase.py` creates and oracle-verifies five hard tasks. Run `PYTHONPATH=src:. pytest tests/worlds_real/git -q` to check 2,000 generated merge cases, replay/rebase sequences and the showcases. Git must be on `PATH`.
