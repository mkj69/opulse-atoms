# Von Neumann world at n = 32

Layer 0 supplies `vn/1` states and bytes, `step`, `poke`, `peek`, state accessors, `@exec`, and the `pc`, `a`, `cell`, `halted` probes. The local given helpers `eq`, `comb_positive`, and `comb_dec` support scoped law and fixpoint reasoning; all invented bodies contain only kernel nodes.

The source routine `sum3_loop` (layer 1) increments its ADD operand at address 3. Its exhaustive scope is all 4096 triples at addresses 29..31 with bytes in 0..15, fresh scratch, and fuel 100. Its contract lists all changed addresses: 3, 27, 28. The first run on [1, 2, 3] leaves the operand 32; resetting only the caller scratch and rerunning produces 34 instead of 6. The changed bytes have a different routine identity and no inherited evidence. `sum3_restored` (layer 2) resets its own ADD operand at address 7; its exhaustive scope is 64 triples in 0..3 with two calls per triple and caller-reset scratch 27. Its contract lists changed addresses 7 and 27.

The relocation arc starts with `source_add` at base 0 and copies its six bytes to base 12. `relocate_add` rewrites absolute operands 28 and 29 to 30 and 31. Both identities receive separate exhaustive evidence over all 16 pairs in 0..3; both contracts list no changed addresses. A copied or retargeted byte sequence without that exact identity has no evidence. `relocate_variant` retargets the copied ADD again to address 29 and is not covered by the relocated routine proof. Its `run_variant` and `variant_result` have their own bounded kernel-definition evidence. With source cells 28=3, 29=1 and relocated cells 30=3, 31=3, the regular relocated result is 6; the variant result is 4.

The three-member variant chain stays separate because each member has a different observable role: `relocate_variant` rewrites code, `run_variant` executes that code as a stateful machine run, and `variant_result` projects the accumulator to a byte. The `run_variant` export uses input (3, 1): its own three-state evidence covers this input, but its `relocate_variant` callee (and that callee's `relocate_add` call) is outside the two-state scopes of those definitions. The example explicitly marks the callee boundary; evidence for the caller does not enlarge evidence for its callees.

The library arc begins with 13 promoted inventions. Layer 1: `SampleProgram` is the fixed program and data image; `run_routine` executes with `@exec`; `next_op` reads the current opcode through `pc` and `cell` probes; `patch_operand` exposes `poke` to later definitions; `twice_run` unfolds to two applications of its plugged operation; `copy_six` copies six instruction bytes. Layer 2: `sum_routine` calls the executor; `reset_operand` repairs byte 7; `relocate_add` copies and retargets two absolute operands. Layer 3: `rerun_restored` repairs before execution; `relocate_variant` retargets another operand. Layer 4: `run_variant` executes from the relocated base. Layer 5: `variant_result` extracts the executed result. Each operation has bounded evidence on its listed inputs with fuel 100; the constant has one closed value; `twice_run` has one state and the `step` operation family. `next_op` has bounded evidence over two states and is used to inspect the Decide task's halted opcode. `run_variant` has three states; its third state deliberately crosses its callee's narrower evidence boundary.

The extension uses the layer-0 equality atom `eq` for byte and complete-state equality. `#restore_idempotent` is checked exhaustively over exactly three complete images of the same restore routine (operand 7 set to 32, 29, or 0); it states `eq(reset_operand(reset_operand(s)), reset_operand(s))`. A derivation rewrites one nested call inside `get_a` with `replay_rewrite`, only on those three images, and charges the final unfolded expression. The deliberately false `#reset_is_identity` fails at operand 7 = 32: the repaired byte is 29, `Ok(false)` after one charged `poke`; it stays callable, without evidence or promotion.

`~relocate_12` copies and retargets the six-byte routine by the invented `relocate_add` program. Its node domain requires all six source bytes, initial pc 0, and equal data at 28/30 and 29/31. The recorded verification scope is exactly the four pairs 0..1 at the two matching data locations, not every input satisfying that predicate. The interface `source_result` / `target_result` executes from base 0 / 12 and compares returned accumulator bytes; the bridge's map returns a whole state, while these two interface operations return bytes. The code-copy-only near-miss on source (3, 1) and target (3, 3) returns 4 rather than the retargeted result 6; the source (3, 1) state does not satisfy the bridge domain.

`retarget_operand[operand]` calls the invented `patch_operand` and has bounded family evidence for bytes 29, 30, 31. Each of its three instantiated operations has its own bounded two-image evidence, cost, contract, content hash, and template dependency; the family evidence alone does not promote an instance. `@fix[reset_operand](s, 2)` is the natural fixpoint mode here: a state with operand 32 changes once, then stabilizes on the second repair; height 1 returns `Bottom(not_stable)`. The stateful execution of the changing program is not memoized, and there are no multiple agents to interleave; neither mode belongs in this story.

The ladder's highest level includes law and bridge evidence scopes. The three existing showcase challenges stay in place: deciding fetched-code mutation requires a longer trace than checking the three-image repair law, while inverting a byte over all 256 candidates requires broader search than checking the bridge on four paired inputs.

`VNLibrary` adapts the core observation verifier, which assumes robot states and zero-argument robot probes. It admits only declared VN probes, checks that the observed value matches `cell(s, pc(s))`, and verifies full-state non-interference and unfolding. It also verifies the closed constant object because the core has no general constant-object verifier. Quoted observation code is not callable: `eval(quote(next_op), [])` returns `Bottom(not_callable)` by atoms-meta 2.5. Quote/eval equivalence is checked for every quoted operation, combinator, and constant object.

Requests to core: generalize observation verification to world-declared state-parameterized probes and provide named constant-object verification. A metered `@exec` hook would support nested reflective execution of code objects; this world uses the given `step` and fuel recursion.

The template and all three instances quote with their provenance intact; `instantiate_code` with the quoted template and a resolver for the invented `patch_operand` reproduces the member's canonical code. The template's name and operation-kind symbol both use `retarget_operand`. Compact ASCII declarations present normalized sorts (`VN` and `int`) and omit pipeline metadata; the full definitions and exact evidence remain in the export. The four assembly routines use the same executor node as `run_routine` for their compact declarations; the routine bytes and ledgers remain the authoritative source. The object's `SampleProgram` sort denotes its own stored image rather than the world-level `mem` representation.

Exported routine examples now pass the full `VN<...>` state used by the machine, not just three input cells. The `sum3_loop` example uses (1, 3, 2), an input within its exhaustive three-cell domain, to distinguish its complete input/output/steps tuple from the invented `run_routine` example on (1, 2, 3).

Routine evidence pins both the core transitive atom/cost digest and the source and live functions of the VN machine and its `reference` module. Core hashes reachable calls, but not source-only edits or every live function in the module. The VN wrapper exposes its current source commitment to the core digest so a source-only change invalidates library evidence as well as the declaration's host digests. Promotion refuses a changed wrapper, a changed `reference.step`, or an atom cost change; core invalidates affected evidence before promotion is attempted.
