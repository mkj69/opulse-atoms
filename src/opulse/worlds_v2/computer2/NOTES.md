# computer@2 depth world

Core 0.5 integration: the tower declares calls to fixed operation slots and every
refined object's valid/canon interface in `depends_on`, matching the new core
content identity and layer rules. Multiplication evidence artifacts are regenerated with the
current core before promotion. The current core observation checker still
rejects parameterized `?mem(s, addr)` and observation inputs `addr`, `x`, `y`;
it also reports pure invented operation dependencies as disallowed. Until the
core supplies a parameterized-probe and public-value observation hook,
`?at` and `?dot_wrap` remain callable, not verified or promoted, with no
evidence or contract until all observation obligations can be checked. No observation is exempted from the core checker. The
byte-only `mul_carry` remains a pure operation counting accumulator wraps.

The layer-zero state is a pure `Machine` card holding four bytes, 256 independent memory bytes, a byte pc and a zero flag. All instructions return new states; `snapshot` is an explicit costed clone. The named register selectors are `Reg.A`, `Reg.B`, `Reg.C`, `Reg.D`; the ASCII literal names are also accepted. Cell 255 is reserved for the modular dot accumulator.

The internal register and memory tuples are a given-sort host representation; the declared `to_card` / `from_card` codec converts them to finite `List` cards and back without changing any valid machine.

Example expressions use the bound input name `s` rather than printing sealed memory and register truth in learner-facing text. Judge-only machines and kernel-checked showcase answers live in `data/showcase_grading.json`; the public export includes only its SHA-256 hash. Requested output-machine probes are never precomputed for the learner.

The eleven public tower cards are `@while_b`, `mul_into`, `Vec`, `?at`, `dot_step`, `@zip_fold`, `dot`, `mul_carry`, `Wide`, `wide_dot`, and `?dot_wrap`. `mul_carry` is an operation on two bytes: `mul_parts` loops over the second byte, counts each wrap of the low-byte accumulator and returns the high and low bytes without constructing or reading a machine. The wrap observation folds over vector cells accessed only through `?at` (whose sole truth read is the granted `?mem` probe); it does not call `wide_dot` or any machine operation. The latter example intentionally uses a new single-element input. Most cards verify on a family of 64 bounded inputs; `@while_b` checks every B in 0..255 in two fixed contexts with two distinct operation slots, and `mul_into` checks all 65,536 (B,C) pairs in one predetermined full-machine context per pair. The scope and the true computed dependency layer are exported per card. Helper invented definitions `mul_tick`, `carry_tick`, `mul_parts`, `dot_step_again`, and `wide_step` also pass the pipeline.

Generic layer-zero additions are integer `inc`, `sub`, `lt`, `le`, and `eq`; byte `byte_add`; address `address`; record constructors `vec`, `wide`, `pair`, `machine_new`; field accessors `vec_base.start`, `vec_base.len`, `wide_base.lo`, `wide_base.mid`, `wide_base.hi`, `first`, `second`; structural tag tests `is_vec_base`, `is_wide_base`; and generic structural zip failure `zip_error`. They are used for structure and small arithmetic, never for calculating a story card. The `Vec` and `Wide` objects validate their record bases with kernel comparison and conjunction nodes through the core refine-object verifier; malformed bases fail as `Bottom(invalid)`.

The original design's `load(snapshot(s),C,addr)` observation was replaced by `?mem{s,addr}`: observations cannot call acting operations. `verify_mul --write --processes 32` records the full verification's UTC date, HEAD commit, process count and all 65,536 checked pairs separately from artifact hash validation; the normal test checks provenance and a seeded subset, while `OPULSE_SLOW=1` opts into a full rerun.

Fixed `FnRef` literals are legal arguments to combinators but the core `nodes.references` does not count them as dependencies. The local `_deps_hash` includes every fixed slot target and its transitive dependencies, so a changed `dot_step`, `wide_step`, `carry_tick` or `mul_tick` invalidates the relevant promotion contract. Delete this local hash extension once the core records fixed operation-slot dependencies.

The core cost account counts only `Definition.body`, which is `None` on refine objects. The local `account` hook counts their actual kernel `valid` and `canon` nodes for a nonzero object definition length.

The design's `@seq` is a given combinator: the tower uses nested `Let` nodes for its sequential instruction blocks. `@zip_fold` is a public `Rec` with a decreasing vector-length measure; replace with core structural-fold combinator when spec 0.3 lands. `@while_b` has no fuel cap: termination follows the strictly decreasing B measure. A cap of 256 layer-zero steps would wrongly stop valid loops. For initial B, its exact cost with the designated `mul_tick` body is `6 + 8*B`; `mul_into` has the same cost. For B=255, both take 2046 steps. The generic combinator has no fixed step maximum independent of its body; for the separately checked `carry_tick` family, the largest B=255 case takes 2859 steps. On 32 terms with both Vec ranges filled with 255, core 0.5 charges `dot` 70681 steps and `wide_dot` 119255 steps (including unfolded argument work at the call site). These are the worst-case term values in those fixed 32-element ranges; initial machine context is zero except for the 64 vector cells. The closed-form multiplication state is `(A+B*C)%256, B=0, C unchanged, D unchanged, memory unchanged, pc=1, z=1 if B>0 else original z`. The predetermined context for each pair is `A=(13*C+7*B)%256`, `D=C xor B`, `pc=(C+B)%256`, `z=(C xor B)&1`, and `mem[i]=(37*i+11)%256`. `verify_mul --write` first regenerates the loop evidence, then checks every full kernel multiplication outcome and exact steps in parallel, recording scope and body/world/dependency/content/atoms hashes in `data/mul_into.evidence.json`; it records the 1024 checked loop runs in `data/while_b.evidence.json`. `verify_mul --while` regenerates only loop evidence. Normal tests recheck 2000 seeded distinct multiplication pairs and the slow opt-in test reruns the full matrix. Showcase Invert derives an affine equation from three full kernel wide-dot evaluations, filters all 1024 inputs by that exact equation, and kernel-rechecks each surviving solution.

Layer-zero `Byte`, `Addr`, and `Mem256` use transparent given host carriers rather than generated refine wrappers: every mutating instruction checks byte/address bounds, and `machine` checks all 256 memory cells. The given `branch` accepts an already evaluated boolean condition rather than a function reference, so its predicate evaluation remains visible as a separate kernel node. The design reuses the eight-element machine for `dot` and `wide_dot`; both examples retain the same input to preserve the specified 198 result. The eleven story positions and their computed dependency layers are deliberately different.

The generated JSON uses `ensure_ascii=True` rather than the shared worker brief's UTF-8 rendering. This preserves every decoded Chinese `_zh` field exactly but is necessary for the existing `test_prepub_cleanup` invariant, which scans raw English-site assets for Chinese characters and does not yet exempt `worlds_v2` records. The browser JSON decoder returns the same values.

For `mul_into`, every one of the 65,536 pairs checks the full machine outcome and layer-zero step formula. The core pipeline separately checks unfold equivalence on its 64 bounded full-machine contexts; the exhaustive sweep does not rerun that inline comparison for every pair.

The `tasks.py` hook supplies finite byte, vector and showcase-memory state domains, machine rendering and a host-value codec. The current generic task generator interprets observations as a single truth-state argument with prebound zero-argument probes, whereas this tower's observations accept explicit machine and address/vector arguments. It also rejects legal literal register names and refined-object constructor bodies when grading invented definitions. Until the generic generator accepts these world interfaces, the hook exposes an isolated task-facing slice of the same library: two small refined scalar objects, two integer operations, two operation-slot combinators and two single-probe observations. The complete tower remains available in the underlying library, unchanged; only the task enumeration view is restricted. These eight task-facing definitions are callable task examples, not promoted tower cards or evidence for the tower.
