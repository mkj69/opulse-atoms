# Calendar@1: century-scale depth tower

## Layer zero

There are exactly 36,525 valid Gregorian dates from 2000-01-01 to 2099-12-31. The Monday=0 weekday probe is anchored at Saturday, 2000-01-01. Neither implementation nor oracle depends on a host time zone. `next_date` fails with `Bottom(range)` at the final day; `date` checks validity, while `eq`, `lt`, `le`, `add`, `subtract`, `indicator`, `pair`, `first`, `second`, `some`, and `optional_date` are generic constructors/accessors/comparisons/arithmetic. Existing `year_of`, `month_of`, `day_of`, `equal_int`, `less_int`, `decrement`, and `fail` support the public measured `day_step`/`@repeat` rule (0..7 days). Their full kernel specs live in the locked declaration's combinator library and are promoted by core. The only truth probes are the granted `weekday` and date-field readings. `maybe_date` preserves `none` and `some(date)` distinctly; the initial fold value is `none`.

## Invented tower

Each numbered card is promoted through write/check/make_callable/verify/account/promote. The tower numbers are presentation positions, not computational layers: export `layer` and `def_layer` both show the computed depth and `tower_position` preserves the design order. Numbers in the last column are layer-zero steps of the exported `Library.run` call with already checked argument values; evidence is bounded unless otherwise stated. Helpers (`month_span`, `count_workday`, `count_every_day`, `next_via_repeat`, `observed_fixed`, `holiday_match`, `keep_open`, and `weekday_is_0` through `weekday_is_6`) are separately verified/promoted but do not appear as tower cards.

## Core issues

### ASCII notation limitations

Story rows preserve the original design copy in `design_decl`. Only `workday` and `seek` have `decl`/`ascii` verified against the stored definition body; the remaining rows have neither field. No hand-written declarations are published. The original algorithms and evidence remain in the stored definitions and the `body` export field.

Printer unavailable: `LeapDay`, `week_later`, `MonthSpan`, `weekday_count`, `Holiday`, `settle` — ValueError: dependencies cannot be represented in their current order; `month_end`, `month_fold`, `nth_weekday` — ValueError: invalid ASCII identifier; `open_day` — ValueError: bool cards are indistinguishable from host bools in ASCII.

Exact evaluated inputs are spelled as `date.ymd<year, month, day>` and, for the fold, the complete `MonthSpan.val<pair<...>>` literal rather than display-only dates. The following five examples cannot round-trip through `notation.parse_expr(text, library)` on this core and retain their exact evaluated arguments as text: `LeapDay.make(date.ymd<2000, 2, 29>)`, `Holiday.make(date.ymd<2032, 11, 25>)`, `Holiday.make(date.ymd<2032, 1, 19>)` (the grammar treats `.make` as a card tag, not a generated operation call); `@seek[next_date, workday](date.ymd<2000, 3, 7>, 3)` and `@seek[next_date, workday](date.ymd<2000, 3, 6>, 3)` (the parser forbids an observation in an operation slot, although the checked combinator accepts its `FnRef`). The shared `finalize_export` parses example text without a library context, so it cannot assign `ascii` to the otherwise parseable `?workday{...}` (two examples), `?open_day{...}` (two examples), or `@month_fold[next_date, count_workday](...)` (one example). All five parse with `parse_expr(text, library)` and round-trip to their evaluated nodes.

An earlier core version renamed a parameter sharing a name with a global atom in both variable and call positions. On the current core, both the direct and unfolded calls below return `Ok(2)`:

```python
from opulse.atoms import kernel, nodes as n
scope = kernel.DictScope([kernel.Atom("weekday", 1, lambda value: value + 1)],
                         [kernel.Defn("f", ("weekday",), n.Call("weekday", (n.Lit(1),)))])
node = n.Call("f", (n.Lit(0),))
print(kernel.evaluate(node, scope=scope).outcome)
print(kernel.evaluate(kernel.inline(node, scope), scope=scope).outcome)
```

The `nth_weekday` input remains named `target_weekday`; the public operation is positional and its behavior is unchanged.

The remaining observation-checker limitation is reproducible on the completed calendar library:

```python
from opulse.atoms.observations import check_observation
from opulse.worlds_v2.calendar.deep import build_library
library = build_library()
assert "operation holiday_match may read or change truth" in check_observation(library.get("open_day"), library)
```

## Deliberate design deviations and adapters

* The core's refine object generator packs one base value; `MonthSpan` therefore refines a generic `(start, end)` pair rather than a two-field object form. Its `month_span` constructor really walks successive dates and validates both endpoints. `LeapDay` and `Holiday` also use core refine constructors, not named constants.
* Core's generated refine accessor now rejects invalid forged cards, and core's checker resolves generated operations and generic edges. The world no longer overrides `run`, `get`, observation parameter inference, or combinator evidence. Equal valid cards remain structurally indistinguishable; the declaration exposes no generic `card` primitive for minting them.
* `MonthSpan` is sealed with only its generated `make` and `base` operations public. Later `month_span`, `month_end`, `month_fold`, and `nth_weekday` definitions use those operations rather than appearing in the object's interface before they exist.
* The core observation checker still rejects a policy operation even when that operation receives only a date reconstructed from granted year/month/day probes. It also follows that policy's date-taking helpers (`week_later`, `next_date`, and seven `weekday_is_N` operations). The world-local `open_day` adapter exempts only those named diagnostics, checks the exact reconstruction on all 50 evidence dates, compares with the oracle, checks no state mutation, and records the exact checked-domain digest via `bound_evidence`. Its body never passes the subject directly to `holiday_match`. All other cards use core checks and verifiers. An injector could still try another synthesized date; consider replacing this world-local check with a generic probe-taint checker in core.
* `nth_weekday` plugs one of seven promoted static `weekday_is_N` predicates into invented `seek`, then calls invented `week_later` for further occurrences. `seek` verifies every plugged accept predicate on its recorded domain. This substitutes explicit slot selection for the design's runtime weekday closure, which the kernel does not provide.
* `month_fold` verifies two semantically identical next-day step implementations, but its body does not enforce slot identity with `next_date`. The measured recursion safely fails if a step cannot reach the end; the contract and tests cover the stated two implementations only.
* `open_day` calls `workday` on the date reconstructed from granted probes, rather than making the weekday comparison itself. An initial `keep_open` check on the month's first date makes `settle` depend explicitly on the invented accumulator; the inclusive fold visits that date again. The repeated observation changes cost, not the final date. Where the design needs independent operations, bodies do not pretend to link to the preceding card: cards 2, 3, 4, 5, 7, 9, and 11 use their declared inputs/slots or other earlier helpers instead of card N-1. In particular `month_fold` takes a checked `MonthSpan` rather than calling `month_end`.

No slow marker is needed: `tests/worlds_v2/calendar` finishes under 120 seconds. The independent all-date weekday test is exhaustive; the promoted pipeline scopes are the smaller families precisely stated above. No core files or other worlds are modified.
