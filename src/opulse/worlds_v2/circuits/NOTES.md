# Circuits depth v1

## Layer zero

`Bit` is zero or one, `Bits` is little-endian, and a `Circuit` is a checked DAG of at most 16 input pins, 16 output pins, and 1024 topologically ordered AND/NOT gates. `and_gate`, `not_gate`, `and2`, `eval_bits`, and the authorized `out_pin` probe are the design's given atoms. Generic graph constructors/accessors, immutable sequence operations, equality, and small-integer arithmetic support kernel wiring, not a host implementation of an invented gate. The given `compose` combinator unfolds with genuine zero-argument `FnRef` operation slots. The graph cache avoids redundant DAG validation and output evaluation without changing kernel steps.

## Tower

Computed layers below are dependency layers: export `layer` is the actual dependency layer and `design_layer` retains the catalogue position. `equiv` uses `first_diff` rather than chaining all ten design positions. Example steps are generated by the kernel rather than copied from the design. `operation_cases` counts the Cartesian operation-slot family separately from the number of value-argument tuples in combinator evidence.

`#xor_comm` checks all four one-bit pairs; `#adder_correct` and `#mult_comm` each check all 256 four-bit operand pairs. These are bounded equations (eligible for scoped rewrites), not unbounded-width identities. Judge-only law verification reads full outputs; tower examples use output probes. The public export redacts DAG values; judge-only examples reside in `worlds/judge/circuits.json`. Learner `Library.run` and its exposed kernel scope reject the full-DAG and full-output accessors, while internal construction and judge evaluation can use them.

The published law examples execute their named laws on integer operands, rather than using one output pin as a stand-in. Invented `Xor` and `Adder8` wrappers are checked against their full refinements when unwrapped or packed; malformed DAGs and gate cards are rejected by the hosts without trusting object identity.

`Adder8.make` recognizes the verified eight-bit ripple DAG and harmless trailing gates whose outputs are not selected. Width and output count alone do not prove adder behavior; other correct but noncanonical implementations are outside this object's constructor contract.

The opt-in depth test checks `truth_table` and all four `out_pin` rows for every one of the 7,508 two-input, one-output graphs with at most three gates. For `first_diff` and `equiv` it pairs each of the 308 at-most-two-gate graphs, in both argument positions, with one representative of each of their nine distinct four-row truth signatures (5,463 ordered pairs) instead of all 308² ordered pairs, which take hours through `Library.run`.

`Xor.make(graph)` and `Adder8.make(graph)` are generated by the core; `Xor.base` and `Adder8.base` unwrap the checked circuit. The two graph builders (`xor_graph`, `adder8_graph`) are promoted operations, not hidden Python graph evaluators. Invalid-width graph construction returns `Bottom(invalid)`. Multiplication builds 730 gates; the full adder builds 22 and the eight-bit adder 178. The exported `first_diff` failure compares 16-input and 2-input circuits and yields `Bottom(index)`; the main witness is `Witness<1,15,16,0>`. All three showcases compare against independently calculated numerical results.

## Limits and adapters

Standalone core `notation.parse_expr(text)` cannot express nine example texts exactly as evaluated:
`pair_graph`, `ripple`, and `equiv` require combinator operation-reference slots
(`@name[operations]` requires a supplied parser context); both `Xor` examples,
`truth_table`, `Adder8`, and both `first_diff` examples call generated object
operations (`Xor.make`/`.base` or `Adder8.make`/`.base`), which the expression
grammar does not accept. Law examples use ordinary call syntax to denote the
same evaluated node without an unsupported `#` prefix. These nine
examples retain their original evaluated expressions, steps, outcomes, and traces.
The export no longer substitutes handwritten operation or `Adder8` refinement
declarations for unprintable stored bodies. Only the printer's definitions
that re-parse to the stored body are published as story `ascii` and `decl`;
the design text stays in `design_decl`. Verified definitions remain unchanged.

`or2` is a nullary circuit constructor, so its core verification has exactly one possible input; its four bit rows are recorded as an additional evidence check, not as four constructor inputs. For `pair_graph` and `ripple`, the core verifies the operation-slot family and the specified widths (only width 4 for `ripple`); separate row checks evaluate the resulting circuits before promotion. Evidence size counts checked rows, not just the core combinator's width arguments. The complete family of all <=3-gate two-input DAGs contains 7508 circuits. Normal evidence bounds `truth_table` to 68 graphs; optional `OPULSE_RUN_SLOW=1` checks the complete family (including OR appended to every graph, with all 4 bit rows), all 308² ordered pairs of <=2-gate circuits for `first_diff` and `equiv`, the reference oracle's exhaustive 65536 byte-pair validation, and independent fresh export regeneration. Default tests build the library and first three cards from scratch; the full independent export comparison is opt-in because it takes longer than 60 seconds. The default suite does not claim to certify the remaining graphs, all 65536 8-bit input pairs, or all pairs of <=3-gate circuits.

Graph-construction operations now use core `Library.verify` for the constructor and unfolding checks, then bind their independently checked truth rows to the evidence digest. `adapter._record` remains only for world-specific authorized-probe observation checks and binds the exact circuit-argument tuples to `scope.checked`; objects use core `verify_object`, and combinators use the core `FnRef` verifier. `eq_bit` compares an output-pin bit with the integer literal for its expected value without weakening the typed `eq_int` signature. I2 checks the unmodified core trace. `CircuitLibrary.check` supplies the generated object-operation signatures to the unchanged core definition checker, and `CircuitLibrary._params` binds observation arguments absent from `ObservationSpec`. Core object validation currently calculates the layer of a refined object with a body from `valid` alone, not the body; the circuit checker preserves the body-derived design layer while still checking the other core object obligations. The library installs the declared given `compose` kernel unfold rule until the core loads world-declared combinators directly. No invented gate's behavior is evaluated by a host adapter.

`first_diff` evaluates output values only through the granted `out_pin` probe, but still uses `dag_inputs` and `dag_outputs` on its supplied circuit arguments to determine the search bound and output arity. If the observation policy treats even this structural metadata as sealed truth, a separately granted shape probe and a re-locked declaration are still needed; no such probe is invented here.
