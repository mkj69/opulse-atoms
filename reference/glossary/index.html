    Glossary¶

    These terms apply to atoms-v2. Display formulas have a separate v3-ASCII copy spelling. Copying does not verify a designed declaration. The Python core parses and checks laws and bridges, but this table does not run those checks. The semantics give evaluation rules, the notation reference gives exact symbols, and the versioned specification describes the implemented subset.

    Designed example

    The illustrative declarations in this table are not verified runs.

    Term Meaning and spelling
    Atom A given or invented object, operation, combinator, observation, law or bridge. The old operation-only meaning belongs to legacy-v1.
    Object A typed value or form, for example 𝔻₁(2, 4). It may compose, refine or seal its representation.
    Operation A typed computation such as a ♦₆ b. Given comparisons use binary signs.
    Combinator A way to assemble computations, such as Θ₁[♡₄₅] 3.
    Observation A read of granted probes or remembered observations, such as Ô₁⟨s⟩. It is not hidden truth.
    Law A statement checked on its declared input scope, such as ≡₁; checking 8-bit inputs would not certify all integers.
    Bridge A translation checked against its declared interface and domain, such as ↝₁(m).
    Mark One glyph from a kind family, optionally carrying an index, layer or prime. The example mark ♦₆ is an operation.
    Index Digits starting 1 to 9 select a defined atom; digits starting with 0 number an overflow given when a kind runs out of unindexed glyphs; a letter identifies a slot; no index means given; a splice computes the reference.
    Slot An atom parameter, not a value: ♦ₐ stands for an operation passed to a template or combinator.
    Given / invented A given is a layer-0 atom; its mark normally has no index, as with ℤ. Invented definitions have layers 1, 2 and so on. A closed kind cannot be invented in that world.
    Splice A computed atom placed in the mark's index: ♦⌞e⌟.
    Layer superscript A left superscript on a header mark records its dependency layer: ¹♠₃ is at layer 1.
    Legend A per-world map from marks to names, kinds, layers and signatures. Its assignments do not alter the global display-to-ASCII token mapping.
    Display form The site-facing Unicode spelling of a formula, for example ♦₆.
    ASCII storage form The unchanged machine declarations in exports and datasets. V3-ASCII (\dia_6) is a separate, one-to-one copy spelling of the display form, not the machine declaration syntax.
    Layer A dependency level. A higher layer can depend on earlier definitions of any open kind, not only operations.
    Template A typed family such as 𝕂₄[𝕏ₜ, ♦ₐ]; its instances need their own evidence.
    Probe / judge view A probe is a permitted read interface. The judge view decides correctness from full state, which may be hidden from a learner.
    Result / outcome Ok(value) succeeds, Bottom(reason) is a domain failure, and Unknown(resource) is exhaustion and never correct. Undefined NaN belongs to Legacy-v1 only.
    Reward A task-specific score or projection. Equal rewards do not prove equal full states or outcomes.
    Evidence / scope A record of method (exhaustive, bounded, seeded sampled), domain, world version and contract. Scope states exactly what was checked.
    Verification / promotion Verification checks the contract on the stated scope. Promotion lets an eligible verified definition be reused as one visible step with that scope; sampling alone cannot authorize it.
    Boundary / unfold A boundary selects which definitions to show as one step. Unfolding expands to layer-0 work without changing outcome or charged cost.
    Fuel A limit on charged layer-0 work. Exhaustion gives Unknown(fuel), not a domain failure.

    Observation is not truth¶

    Executable

    The shadows world export, version 1, grants the top and side probes. Two distinct volumes built with its host constructors have the same top projection. Run this from the repository root with PYTHONPATH=src:

    from opulse.worlds_v2.shadows.deep_hosts import front, to_card, top

first = to_card(((1, 2, 0), (4, 5, 1)))
second = to_card(((1, 2, 3), (4, 5, 1)))
print("same full state:", first == second)
print("same top view:", top(first) == top(second))
print("same front view:", front(first) == front(second))

    Output, computed at build time from the host functions:

    same full state: False
same top view: True
same front view: False

    The export grants learners top and side, not front; the front comparison is an external check, not a learner action. A learner reading only ?top{body} cannot distinguish this pair. The judge view is full state, so a matching observation does not establish equality. This is a host-level computation on constructed values, not a kernel verification record. The export has no sealed object pair: Volume is given and unsealed. Observation rules explain the boundary between probes and truth.

    Designed example

    To teach this ambiguity with sealed values, a future world could define a sealed volume object. It could expose only a top-view observation for distinct hidden bodies that share a top view. This extension is not in the linked shadows historical export. Design record: shadows world, depth pass (11-04). That record proposes projection-only learner views; the seal is an additional proposal.
